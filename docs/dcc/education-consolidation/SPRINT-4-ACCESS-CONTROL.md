Main middleware.ts invokes isPublicRoute from lib/auth/public-routes.ts. Marketing /workshop and /workshops, /api/workshops, /api/organizations, /api/analytics and /api/workshop-live-sessions are public prefixes. Org workshop pages require sign-in, but a session is not org membership; other org pages may be public. middleware-tenant.ts is not the main entrypoint. Next config host rewrites and redirects need regression coverage. Implement server authorization within each handler and shared resolver; never rely on navigation or frontend hiding. Public catalog uses allowlisted DTO only, owner/tenant derived from trusted server identity, published+active+public offering and explicitly approved curriculum version/chapter; partner grants for nonpublic delivery must be valid, version/scope specific and revocable. Unknown state, missing approval or invalid tenant denies. ### Consumer map — principal paths and compatibility
- DccWorkshopsCatalogClient / DccWorkshopPublicDetail fetch public organization list/detail URLs not present as explicit routes in pinned App Router tree. Check generated route manifest, actual deployed rewrite and callers before repair. Catalog config defaults to Oolite; keep existing authorized partner listings until explicit tenant decision.
- Public marketing chapter page/API uses workshop slug allowlist; disk reader lists .md without chapter-level publication flag. Org chapter pages delegate to resolveOrgChapterParam (tenant row lookup and disk index), plural aliases redirect to singular; sign-in alone is insufficient for private content. WorkshopChapterReader consumes learn chapter list/detail API. Enforce one authorization predicate across UUID, canonical slug, numeric alias, plural/singular and legacy learn paths. Validate path grammar/containment, use safe Markdown, deny unreviewed material; preserve existing public Vibe/3D School and partner routes.
- Legacy content authoring route uses signed-in user and hardcoded institutional filesystem path; retire runtime authoring in favor of reviewed Git content. No filesystem writes from public/student runtime. Keep any editor replacement restricted and audited.
- Workshop detail/list routes and analytics mix service-role reads, some with active membership/role checks and others without explicit publication/tenant guard. Separate public projection and authorized staff/member access. Avoid full-row logs and response spreads. Staff create/update/delete checks must derive owner from stored offering, validate input, prevent reassignment, enforce active membership; no destructive delete of learning history without approval.
- Progress uses authenticated Clerk actor but service role; validate enrollment, chapter-parent/tenant relationship, bounded typed input and idempotency; never accept completion as verified ability. Learner can only read own records, staff only permitted aggregate/operational view.
- WorkshopSessionManager calls sessions, resources, bookings; coordinate issue #73. Existing session scheduling uses legacy relations and booking side effects; do not enable or test against production until resource ownership and transactional capacity are established. Live classroom store has DB/memory/cookie fallback; join code is not facilitator authority, keep participant/facilitator roles separate and preserve legitimate live flow. Do not seed missing tables just to make route succeed.
- Legacy Learn Canvas hooks/services include mock or direct client calls, mismatched filters, absent relation names, localStorage enrollment and mock subscription. Current hooks request /api/learning/track-activity and workshop-like paths not located in tree; treat as unresolved contract, not working feature. Do not trust client role or subscription claims. Inspect databaseService actual import graph and all direct SDK consumers before revoking grants.
- Registration, mail/reminders, calendar, interest, votes, courses and sharing require explicit scope/ownership. Disable unneeded dev mail route in production via reviewed change; isolated fake mail sink and idempotent worker for tests; never contact actual learners. Do not create alternate course system merely to satisfy dormant endpoints.

## Authorization and regression contract

Positive tests must preserve existing public chapter/cultural routes, published partner catalog, active member/owner workflows, and approved facilitator operations.
